# 数据绑定细则

[ui-design](../SKILL.md) 的数据侧约定。Step 3「只用 tokens」管的是**视觉值**；本文件管它的对偶——**数据值**。

## 核心规则

**后端接口已经约定的字段，前端不许用常量顶替。**

包括但不限于：

| 类别 | 例子 | 正解 |
|---|---|---|
| 值 | 余额、额度、价格、数量 | 走接口返回的金额字段 |
| 币种与单位 | ¥ / $ / USD / CNY / tokens / 次 | 走接口的 `currency` 或平台结算币种配置 |
| 渠道名 | 支付宝、微信支付、Stripe、USDT | 走接口返回的 `channel` + 渠道常量表映射 |
| 枚举与状态 | 订单状态、支付状态、角色 | 走接口枚举值 + i18n key 映射表 |
| 展示名 | 用户名、空间名、模型名 | 走接口返回的显示字段，不本地拼 |

**判据不是「看起来像常量」，而是「后端是否已经定义了它」。** 后端有字段 → 前端不许自己造一个等价值；有接口但 test 没返回 → 附证据开单钉后端，不许静默改成常量。

## 为什么

- **显示与事实脱节**：写死 `¥` 时，国际站结算币种是 USD，页面就骗用户（真实案例：控制台顶栏余额按站点写死 `¥/$`，而余额接口本身带 `currency` 字段——同一个仓库里账单页已经走 `platform_config.settlement_currency`，顶栏漏了）。
- **多市场/多站点必然分叉**：写死值只在它被写死的那个站点成立，换个站点/币种/市场就是错的。
- **静默漂移**：接口改了枚举值，前端常量表不跟着改，页面继续显示旧值且不报错。

## 落地做法

1. **先找字段真源**：实际请求/响应与运行时日志是字段真源；类型定义和注释只作辅助。日志缺失才复现请求。
2. **有字段就走字段**：金额取接口值；币种取接口 `currency` 或平台配置；渠道名取接口 `channel` 再过常量表映射成展示名。
3. **兜底要集中、要有注释**：接口字段缺失时允许兜底，但兜底值必须集中在**一个常量模块**里，并写明「后端未下发时的按站点兜底」；不在页面里就地写死。
4. **确实没有接口的值才用常量**：并集中登记，说明它为什么是前端常量（法律实体名、静态枚举全集等）。
5. **冲突不自行选边**：接口有字段但值不合理 → 贴证据回后端/需求方，不在页面层造第二个真源。

## 与「只用 tokens」的关系

| | 视觉值 | 数据值 |
|---|---|---|
| 真源 | 设计 tokens | 接口 / 平台配置 / 常量表 |
| 硬编码 | 裸 hex / rgb / px 魔数 | 与接口字段等价的常量 |
| 例外 | 1px 边线、栅格结构尺寸 | 接口无此字段的静态枚举、法律实体名 |

两边的判据一致：**先问「真源在哪」，再问「这个值该不该由我决定」**。

## 自查

- 新写的金额/币种/渠道/枚举展示，值的来源能在代码里指到具体字段或集中常量表吗？
- 这个页面在**另一个站点/市场/币种**下还成立吗？
- 后端改了字段值，前端会跟着变，还是会静默显示旧值？
